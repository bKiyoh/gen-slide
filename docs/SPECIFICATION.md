# Generative Slide System — 実装仕様書 v1.0

ステータス：**レビュー合意済みの仕様**。各Phaseの実装に先立ち、対象Phaseの範囲を確認する。

## 1. プロダクト概要

### 目的
Vue 3 + Three.jsで、四角形を中心とするモーショングラフィックスを**ユーザーがGUIから制作**できるアプリを実装する。作成したアニメーションを独立した `Transition` として保存し、Vueのスライド間切り替え時に再生する。

### 主要な体験

1. Transition Editorを開く。
2. Shapeを個別追加、またはShapeGroupから複数の図形を生成する。
3. Shape・Generator・Modifierの各パラメーターを調整する。
4. 各図形・グループにキーフレームを設定し、Staggerで時間差を作る。
5. 再生とシークによって動きを確認する。
6. Transitionを保存する。
7. プレゼンテーションの任意のスライド間に割り当てて使用する。

### 代表的なサンプル意匠

| 名前 | 表現 | 主な検証機能 |
|---|---|---|
| Diagonal Sweep | 赤と青の平行四辺形が斜めに駆け抜ける | Linear Generator、Alternate、Stagger |
| Block Expansion | 長方形が拡大して画面を覆う | Scale、Group Animation |
| Alternating Slide | 左右から赤青の四角形が交互に現れる | Individual Animation |

これらは**制作例／テスト素材**であり、固定テンプレートしか編集できないアプリにしてはならない。

## 2. 技術と制約

- Vue 3（Composition API / `<script setup>`）、Vite、JavaScript + JSDoc。
- 描画はThree.js `WebGPURenderer`を第一候補にし、実行時のバックエンドを確認できるようにする。Three.jsとGPU APIの詳細は対象バージョンの公式資料を確認する。
- 2D中心、1920×1080の論理座標、左上原点、X右・Y下。16:9の表示領域にフィットする。
- DomainとEvaluatorはVue・Three.jsに依存しない。
- localStorage自動保存とJSONファイル入出力。Cookie・サーバーDBは使わない。
- 発表時はネット接続に依存せず動作する構成とする。

## 3. 機能仕様

### F-01 Shape

- 長方形、正方形、平行四辺形を基本とする。台形・任意四角形は拡張候補。
- 幅・高さ・傾斜・色・不透明度・位置・回転・スケールを編集できる。
- 形状は頂点から生成し、描画処理と分離したデータで保持する。

### F-02 ShapeGroup

- 複数図形を共通のTemplateから生成する。
- **Linear**：個数、開始位置、X/Yステップ。
- **Grid**：行・列、X/Y間隔、行/列のオフセット。
- 生成順に安定IDを与える。個数変更でも既存のOverridesを維持する。
- グループ全体と生成した個々のShapeを別々に編集できる。

### F-03 Modifier

- 規則的に色・サイズ・角度・透明度・位置オフセットを変化させる。
- 最初は `alternate`（交互）と `linear`（等差的な変化）を実装する。
- 複数適用でき、上から順に計算する。衝突する同一プロパティは後勝ち。
- `random(seed)` / `sequence` は拡張対象。

### F-04 Overrides

- 生成された特定の図形だけ設定を変更できる。
- TemplateやGeneratorの情報を消さず、差分のみ保持する。
- Generatorによって再配置した場合も、個別の位置オフセットが維持される。
- 個別上書きの解除をUIから行える。

### F-05 Animation

- プロパティ単位のKeyframe Track。
- 初期対象は位置、回転、スケール、不透明度、傾斜。
- 補間は `linear`、`easeInCubic`、`easeOutCubic`、`easeInOutCubic`。
- Group（親として合成）、Child（共通の相対変化）、Individual（同じプロパティではChildより優先）。
- `localTimeMs = timeMs - index * staggerMs` による時間差。
- 指定時刻から直接評価し、逆方向シークや一時停止後の再開でも結果を再現できる。

### F-06 Transition Editor

- 4領域：左にレイヤー、中央にプロパティ、右上に小型プレビュー、下に常時表示のタイムライン。2026-11-20の回答 `UI-UX-01` に基づく。
- 通常の1366×768以上の表示領域ではページスクロールなし。項目が多い一覧内のスクロールは許容する。小さい画面・低い表示領域では到達性を優先して縦配置にする。
- プレビューは既存Canvasの幅・高さを約半分にする。1440×900で約384×216を目安にし、必要時に拡大できる。ライブラリ・発表構成・ファイル操作・演出設定は必要時にダイアログを開く。
- ShapeとGroupを作成・選択・編集・削除できる。
- プレビューは16:9、再生・停止・一時停止・シークに対応する。
- 数値入力による編集を先に完成し、プレビュー直接操作（ドラッグ・回転・拡縮）を後から実装する。
- ベース編集とキーフレーム編集を「見た目を編集／動きを編集」で明確に区別し、自動的なキー追加はしない。キーの値・時刻・補間は中央、シーク・キー時刻のドラッグは下のタイムラインに集約する。
- ユーザーは**見たままの値**を入力し、absolute/relativeの扱いは内部へ隠す。
- 将来的にUndo/Redo、キーフレームのドラッグ調整を追加する。

### F-07 保存

- `schemaVersion`付きProjectをJSONとしてシリアライズする。
- 編集完了後約500msでlocalStorageへ自動保存。起動時に復元。
- JSONエクスポートとインポートを提供。2026-11-21のユーザー指示により、インポートは既存の演出・スライドを残して末尾へ追加する。
- 読み込み時に検証し、不正データなら既存データを保護する。衝突するIDとスライドの演出参照を調整し、Overrideとキーを維持する。追加は履歴1操作でUndo/Redoでき、追加前の履歴も保持する。
- 保存容量超過やデータ破損はUIにエラーを表示する。
- ブラウザや端末をまたぐ同期機能は設けない。必要に応じてJSONを持ち運ぶ。

### F-08 Presentation

- 各スライドはVueコンポーネントで実装する。
- スライドに**次へ進む時に使う**Transition IDを割り当てる。
- キーボードによる前後移動、フルスクリーンに対応する。
- GPU CanvasをDOMスライド上に重ね、Transition実行時のみ可視化する。
- 指定の`switchAtMs`でスライドを変更する。変更は一度だけ。
- 図形が全画面を覆わなくても演出を再生し、指定時刻で切り替える。遮蔽は演出の表現に任せる。2026-11-19のユーザーフィードバックを受け、単色cover機能と遮蔽の必須判定を廃止した。
- Transition失敗時にスライド操作を失わないようフォールバックする。
- 切り替えの多重起動は防止する。

## 4. データフローと処理契約

データモデルの例、優先順位、演算規則の詳細は `docs/DESIGN.md` を参照する。

```text
Project → Transition → Shape / ShapeGroup
    ↓
Template → Generator → Modifier → Overrides
    ↓
Animation Evaluator (timeMs)
    ↓
Group Transformの合成
    ↓
Three Renderer → Canvas
```

必須条件：

- 同じTransitionと同じ時刻は同じ描画状態を返す。
- ドメインデータを評価処理の副作用で書き換えない。
- 共通アニメーションと個別アニメーションの同一プロパティは個別を優先。
- GroupのTransformは子のローカル状態に対する親の変換として合成する。
- Editor と Presentation で同じ評価ロジックを利用する。

## 5. 開発Phaseと受け入れ基準

**次のPhaseに進む前に各Phaseをレビューすること。** 詳細なPhase 0指示は `docs/phases/phase-0.md` を参照。

| Phase | 実装対象 | 完了条件 |
|---|---|---|
| **0** | Vue + Three.js描画基盤 | 赤い長方形・青い平行四辺形、パラメーター変更、16:9、WebGPU使用確認、GPUリソース解放 |
| **1** | Shape / ShapeGroup、Generator、Modifier、Overrides | 赤・青の平行四辺形を10個生成、個別上書き、生成ルール変更時の保持 |
| **2** | Keyframe Evaluator、Easing、Group/Child/Individual、Stagger | 複数図形が時間差で動き、任意時刻を再現できる |
| **3** | 基本Editor、タイムライン表示、数値編集、JSON/localStorage | GUIだけでTransitionを1つ作成・再生・保存・復元できる |
| **4** | Vueスライドとの統合、切り替え、キーボード、全画面、失敗時対応 | 3枚以上のスライドを異なるTransitionで切り替え、オフラインで再生できる |
| **5** | 直接操作、キーフレームのドラッグ、Undo/Redo | 視覚的な操作で意匠・タイムラインを編集できる |
| **6** | Radial / Random / Path、追加Modifier、表現拡張 | LT後の任意機能。必須要件ではない |

### Phase間の優先順位

- 目的はLTで使用できる作品を完成させること。Phase 3の数値編集・保存ができたら、Phase 4のPresentation連携を先に実装する。
- Phase 5〜6の高度なUI／表現はLTの必須条件に含めない。
- 技術基盤が不安定なら先にそこを解決し、後続機能を先回りして実装しない。

## 6. 非機能要件

### 性能
- 60fpsを目標とする。ただし性能の保証値ではない。ブラウザ／GPU／画面解像度で異なる。
- フレームレートに依存しない時刻評価とする。
- 不要なGeometry/Materialの再生成を減らし、破棄漏れを防ぐ。

### 安定性
- 初期化失敗時は原因が分かるメッセージを表示。
- リサイズで表示が崩れない。
- 演出失敗時でもスライド移動が可能。
- JSON破損やバージョン違いで既存の保存データを破壊しない。

### 保守性・学習性
- 数値計算は可能な限り純粋関数とし、ユニットテスト可能にする。
- GPU描画の処理は短い責務ごとのファイルに分け、処理の流れが追えるようにする。
- 不要なライブラリ・複雑なパターンは追加しない。

## 7. テスト戦略

- Domain/Generator/Modifier/Evaluator：Vitest等によるユニットテスト。
- 入力の境界値：図形数0／大きすぎる値、NaN、負のサイズ、不正なカラー、不正な時刻など。
- 描画：ブラウザで実描画・リサイズ・破棄を確認する。
- Editor：ベース編集／キーフレーム編集、グループ内の上書き、保存／再読み込みを確認する。
- Presentation：遷移の前半・切替瞬間・後半、多重操作、失敗時フォールバックを確認する。
- ビルド・テスト実行状況と未検証事項をPhaseごとに報告する。

## 8. 初期対象外

動画出力、PowerPoint/PDF出力、スライドの本格GUI編集、共同編集、クラウドDB、認証、GPU物理演算、任意3Dモデル、多階層ShapeGroup、複数の独自Rendererの並行実装。
