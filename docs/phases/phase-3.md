# Phase 3 — Transition Editor・タイムライン・保存

**Codexへの実装指示。Phase 2がレビュー承認済みであること。Phase 4以降には進まないこと。**

## 0. 着手前の確認

`AGENTS.md`、`docs/DESIGN.md`、`docs/SPECIFICATION.md`、本書を読む。Phase 1の静的評価とPhase 2の `evaluateTransition(transition, timeMs)` の契約を確認する。既存のVue画面と描画リソースのライフサイクルを把握する。

## 1. 目的

**GUIのみでTransitionを1本制作し、再生・シーク・保存・復元できる最小限の制作ツール**を完成させる。数値編集を優先し、ドラッグ移動／タイムラインのキーフレームドラッグはPhase 5へ委ねる。

## 2. 画面設計

4領域のEditorを作る。各パネル名・責務は以下。

| 領域 | 機能 | 今回必須の操作 |
|---|---|---|
| Layer Panel | TransitionのShape/ShapeGroup階層を表示 | 追加、選択、削除、複製、順序変更（必要ならボタン） |
| Preview | 16:9で時刻tの描画結果を表示 | 再生・一時停止・停止・シーク、選択状態表示 |
| Property Panel | 図形・グループ・生成規則・動きの編集 | 数値／色／選択肢による編集、個別Override解除 |
| Timeline | トラックとキーフレームの表示 | 時刻指定、キー追加／削除、数値／時刻／Easing編集 |

- 選択対象がShapeかGroupか生成子itemかでProperty Panelを切り替える。
- プレビューは発表時の1920×1080論理領域を等比表示する。
- 画面の縦横サイズが小さくても必要な編集が可能なスクロール・リサイズ方針とする。
- Undo/Redo、プレビュー上のドラッグ移動、キーフレームのドラッグ編集は今回実装しない。

## 3. エディタの状態管理

- **Projectデータ**（保存対象）と **Editor UI状態**（選択中ID、現在時刻、再生中、タブ、ズームなど）を分離する。
- EditorからDomain計算へ渡すデータはプレーンなJSオブジェクトとする。
- Three.jsオブジェクト、`requestAnimationFrame` ID、DOM参照をProjectへ保存しない。
- 1回の編集操作は意味上の1更新として扱う。Phase 5でUndo/Redoを追加しやすいよう、更新経路を集約する。ただし大規模なコマンドフレームワークは不要。
- UIで無効な入力を確定させない。エラーと修正方法を表示する。

## 4. Transition管理

- Transitionの新規作成・名前変更・選択・複製・削除ができる。
- 1つのTransitionは、`durationMs`、`switchAtMs`、`layers`、`cover` を持つ。
- `0 <= switchAtMs <= durationMs` を検証する。
- 今回はPresentationでスライド変更を実行しないが、`switchAtMs` と `cover` を編集・プレビューできるようにする。
- ShapeとShapeGroupを追加し、レイヤー順（表示順）を変更できる。
- Layer/TransitionのIDは衝突しないよう生成する。複製時は新しいIDを割り当てる。Group配下のOverrideキーは有効なままコピーする。

## 5. Generator・Modifier・OverridesのGUI

### Shape / Generator

- Shapeは形状、位置、サイズ、回転、スケール、色、透明度を編集可能。
- ShapeGroupのTemplate、Generatorの `linear`/`grid`、count/rows/columns/間隔/開始位置を編集可能。
- Generator変更時は自動生成子の再評価を行い、既存Overridesは保持する。

### Modifier

- `alternate`、`linear` を追加・削除・順序変更・有効/無効にできる。
- 対象プロパティを選び、方式に応じて値を入力できる。
- 同一プロパティに複数Modifierがあれば、**後勝ち**であることをUI上で分かるようにする。

### 個別Override

- Group子の `item-xxx` を選択し、変更されたプロパティのみOverrideとして保存する。
- 個別位置は生成位置からのオフセットとして保存する。
- 上書き中の項目を識別可能にし、項目ごとに共通設定へ戻せる。
- 子の生成数を一度減らして戻しても既存Overrideを復元する。

## 6. キーフレーム編集と『見たまま編集』

### 6.1 二つのモード

- **ベース編集**：基本Shapeや静的Overrideの値を変更する。
- **キーフレーム編集**：現在時刻を選んで、既存キーを編集する／明示的にキー追加して値を決める。
- 単に数値欄を変更しただけで自動的に新規キーフレームを作らない。

### 6.2 キーフレームの操作

- Layer／Group／Child／Individualのトラックを選べる。
- 対象プロパティのTrackを追加できる。
- キーフレームの追加、時刻と値の変更、Easing変更、削除ができる。
- 重複時刻をUIで検出し、保存を防止する。
- `staggerMs` を設定でき、グループ内で開始タイミングがずれる。
- 位置・回転・スケール・不透明度・傾斜について、Phase 2の評価に反映する。

### 6.3 最終表示値と内部値の変換

合意済み方針：**ユーザーは画面に見えている値を編集し、Absolute/Relativeの演算は内部で扱う。**

- プロパティ表示はできるだけ**現在時刻の最終表示値**と整合させる。
- 個別Shapeの最終座標を設定したとき、親Groupの変換があれば**逆変換して**子のローカルなOverride／Track値を求める。
- 既存Modifier値やChild Animationを加算し直さないよう、編集対象の階層と編集モードを基準に差分を計算する。
- **グループTransformが逆変換不能（例：scale=0）**なら、該当操作を拒否し理由を表示する。不正な値を保存しない。
- 全ての編集操作でWorld座標の逆算が難しい場合、**操作対象を明示してUIで制限**し、できない操作をできるかのように見せない。制限は実装報告に列挙する。仕様に反する暗黙のローカル値表示へ切り替えない。
- この変換ロジックはUIイベント内に散らさず、テスト可能な関数へ分離する。

## 7. 再生・シーク

- `requestAnimationFrame` による再生時計をEditor側に実装する。計算は実経過時間（ミリ秒）から `evaluateTransition` を呼ぶ。
- 再生、停止（先頭に戻す）、一時停止、再開、現在時刻の手入力／スライダーシークを実装する。
- 終端で停止し、再生開始時に時刻0へ戻せる。
- 非表示タブからの復帰時に時間ジャンプが生じても描画結果とUIが不整合にならないようにする。
- 再生中の編集による評価更新、コンポーネント破棄時の再生停止を保証する。
- `switchAtMs` に達した場合、Editorでは**スライドを変更しない**。coverの表示だけプレビューする。

## 8. 永続化・JSON入出力

- `Project`全体を`schemaVersion: 1`付きJSONとして保存する。
- 編集確定後**約500msのデバウンス**で `localStorage` に自動保存する。
- 初回起動はサンプルProjectまたは空Projectから開始する。復元可能な保存データがあれば優先する。
- 保存状態の表示：保存中、保存済み、エラー（容量超過や書込不可）。
- JSONエクスポート：プロジェクト全体をファイル化。
- JSONインポート：パース → スキーマ・参照・範囲・ID検証 → 確認／適用。**検証完了まで既存Projectを変更しない**。
- 不正JSON、非対応schemaVersion、ID重複、存在しないTransition参照、キーフレームの重複時刻、描画負荷が過大な設定などを扱う。
- `localStorage`読み込みエラー時は現データを消去せず、再取得／インポートできる手段を残す。
- 保存先のキー例：`generative-slide-system.project.v1`（アプリ専用で衝突を避ける）。
- Editorの一時UI状態は原則保存対象外。**保存時にGPUやDOMインスタンスが混入しない**ことをテストする。

## 9. 動作確認シナリオ

1. Transitionを作成する。
2. 平行四辺形のGroupを10個Linear配置し、赤青交互にする。
3. 幅のLinear Modifierを追加する。
4. 3番目だけ白色へOverrideする。
5. Child Animationで移動のキーを3つ作り、Stagger 40msを指定する。
6. 3番目へIndividual回転トラックを追加する。
7. 0ms／中間／終端へシークし、表示を確認する。
8. `switchAtMs` とcoverを設定し、前後の見え方をプレビューする。
9. リロード後に復元を確認する。
10. JSONエクスポート→インポートし、設定と再生結果の一致を確認する。

## 10. テスト・確認項目

- Transition／レイヤー／キーの追加・削除・複製でIDが整合する。
- Generator・Modifier・Overridesの変更がRendererへ反映される。
- ベース編集とキーフレーム編集が混在しても誤上書きしない。
- 再生・停止・シークで時刻と描画が一致する。
- 逆変換で指定した表示座標が再現される。非可逆状態は安全に拒否される。
- デバウンス中に連続編集しても最後の値を保存する。
- JSONラウンドトリップで意味的に同じProjectが得られる。
- 保存失敗・不正JSON・未対応バージョンで既存データが壊れない。
- Rendererがアンマウント時に適切に解放される。
