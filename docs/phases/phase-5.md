# Phase 5 — 直接操作・キーフレームのドラッグ・Undo / Redo

**Codexへの実装指示。Phase 4レビュー承認後に着手。Phase 6へ進まないこと。**

## 0. 着手前

`AGENTS.md`、`docs/DESIGN.md`、`docs/SPECIFICATION.md`、本書を読む。Phase 3のEditor状態管理／更新API／描画座標変換、Phase 4のPresentation安定動作を確認する。高度なUI追加で既存の制作フローを壊さない。

## 1. 目的

数値入力だけでなく**プレビューで直接図形を動かし、タイムラインでキーフレームを操作し、編集を取り消せる**ようにする。新しい描画方式ではなく、既存のDomainとEvaluatorの編集操作を改善するPhaseである。

## 2. プレビューの直接操作

### 2.1 図形選択

- 描画範囲のクリック／ポインター操作で対象Shapeを選べる。
- ShapeGroup内の生成子も個別に選択できる。Group全体の選択との切替方法を明示する（例：レイヤー選択が優先、子選択モードを用意）。
- 複数図形が重なる場合は、**描画順に基づく手前の図形**を選ぶ。
- 背景クリックは選択解除。非表示／編集不可レイヤーがあるなら選択対象から除外する。

### 2.2 移動・回転・拡縮

- 図形をドラッグして移動。選択枠のハンドルで回転／拡縮する。
- 表示領域のCSSサイズと1920×1080論理座標との**等比変換・逆変換**を共通ユーティリティで扱う。レターボックス余白内の操作は無視する。
- Groupの親Transformを考慮し、子のワールド座標でのドラッグ結果からローカルなOverride／Keyframe値を逆算する。
- 矩形／平行四辺形の見た目に合うHit Testを用いる。最初は回転・傾斜した四角形を含む形状判定でよい。GPUピッキングは必須ではない。
- 変形時のピボット（図形中心）と回転正方向はPhase 2の契約を維持する。
- スケールが0、計算不能な逆行列、非有限数など、**安全に逆変換できない操作は拒否して通知**する。
- 形状の4頂点を自由にドラッグする機能は今回の対象外。

### 2.3 ベース編集／キーフレーム編集

- UIのモードに応じて、ドラッグ結果の保存先を切り替える。
- ベース編集：Shapeの基本値、または生成子のOverridesへ反映。
- キーフレーム編集：明示的に選択／作成した対象キーへ反映。**単なるドラッグで勝手に新しいキーを増やさない**。
- 両モードで**画面に見える座標・回転・大きさと最終結果が一致する**よう計算する。
- 同じ内容をプロパティ数値入力したときの結果と整合すること。

## 3. タイムラインのドラッグ編集

- 再生ヘッドのドラッグで時刻シーク。
- キーフレームをドラッグして時刻を変更する。
- 他のキーフレームとの同時刻衝突を防ぎ、連続キーの並び順が壊れないようにする。
- スナップ単位（例：10ms）を導入する場合、設定や操作方法を示す。単位はミリ秒。
- Group／Child／Individualのトラック区別が崩れないように表示する。
- Easingの編集はPhase 3の既存UIを引き続き使う。ベジェカーブ編集は必須ではない。
- 再生中にキードラッグを始めた場合、再生を一時停止するなど矛盾のない操作を定義する。

## 4. Undo / Redo

- EditorのProjectデータ変更に限って履歴を管理する。再生時刻、選択、ズームなどの一時UI状態は履歴対象外。
- 対象：Shape/Group作成・削除・移動、生成パラメーター変更、Modifier追加・編集、Override、Keyframe追加・編集・削除、ドラッグ変形。
- **一度のポインタードラッグを一つの履歴単位**として扱う。mousemoveごとに履歴を積まない。
- Undo後の編集ではRedo履歴を破棄する。
- 保存済みProjectと履歴の関係を定義し、Undo後の状態が自動保存されるようにする。
- 履歴件数に上限を設ける。大きなProjectでも無制限にメモリが増えないこと。
- JSONインポート時の履歴は**新しい起点としてクリア**することを推奨する。
- キーボードショートカットは `Ctrl/Cmd+Z` と `Ctrl/Cmd+Shift+Z`（環境に合わせてRedoの代替キーも可）。入力欄内の通常編集と競合させない。

## 5. UI／操作性

- 選択中オブジェクトが分かる選択枠・ハンドル表示。
- ドラッグ・数値入力時の変更をプレビューへ即時反映。
- 編集不能な状態（非可逆変換・データ不正）を無言で無視せず、原因を表示。
- ポインターキャンセルや画面外への移動でも編集状態を正常終了させる。
- 操作中の再描画・イベント登録が蓄積しない。
- 小さな画面や高DPI表示でもヒット判定がずれない。

### 5.1 UI-UX-01の回答に基づく配置改善（2026-11-20）

- 左にレイヤー、中央にタブで切り替える編集欄、右上に小型プレビュー、下に常時見えるタイムラインを置く。
- 既存Canvasの面積約1/4（幅・高さ約半分）を基準とし、1366×768で通常操作にページスクロールが不要なこと。項目が多い一覧内のスクロールは許容する。
- ファイル操作・演出設定・ライブラリ・発表構成・開発用サンプルは必要時に開き、単なる開閉で選択・再生時刻・履歴を失わない。
- 「見た目を編集／動きを編集」を中央にまとめ、キーの詳細編集も中央へ配置する。データの意味と保存先は既存の契約を維持する。
- 1366×768、1440×900、1920×1080と小さい画面で到達性を確認し、直接操作・Undo/Redo・保存・発表の回帰も確認する。

## 6. 検証シナリオ

1. Groupの子をクリックして選択し、画面上でドラッグ移動する。
2. 親Groupに回転がある場合でも、子の移動結果がポインター位置と一致する。
3. ベース編集で移動→Generatorの間隔変更を行い、個別オフセットが維持される。
4. キーフレーム編集モードで選択キーだけ変更し、他のキーや共通アニメーションを壊さない。
5. 回転・拡縮・キーフレーム時刻をドラッグ編集する。
6. 一連のドラッグをUndo 1回で戻し、Redo 1回で再適用する。
7. Undo後に別編集するとRedoが無効になる。
8. 保存→再読込で最後に確定したProjectと表示状態が一致する。
9. Phase 4のPresentation再生で既存Transitionが破損していない。

## 7. 自動テスト

- スクリーン座標→論理座標→スクリーン座標の往復。
- 親Transform有無の逆変換、回転・スケールの境界値。
- レイヤー重なりの選択優先、非選択対象の除外。
- ベース編集とキーフレーム編集の書き込み先の差。
- ドラッグ完了1回に対する履歴1件。
- Undo／Redo／Redo破棄／履歴上限／Import時リセット。
- キーフレームの並び順、ドラッグ衝突防止、再生中の扱い。
- 編集後のProjectが再びEvaluatorで正しく評価できる。

## 8. 実装しないもの

- 自由形状の頂点ドラッグ、描画内容の動画出力、グループの多階層ネスト、物理演算、タイムラインの本格マルチトラック合成、Radial／Random／Path。
