## 主な設計判断

ProjectはshallowRefでプレーンなデータを保持し、選択ID・編集モード・時刻・再生状態・入力途中の値・DOM参照は別のUI状態に置いています。ProjectにはThree.jsオブジェクトやRAF IDを入れません。

編集は `applyProjectEdit(project, edit)` に集約しています。現在のProjectを複製 → 一操作を適用 → 全体を検証 → 成功時だけ置換する流れです。無効な操作では元データも保存値も変えません。Undo/Redoや大規模なコマンドフレームワークは追加していません。

IDはProject内のTransition・Layer・Slide全体で重複しないように生成します。Transitionの複製では配下Layerも新IDにします。GroupのOverrideキーとIndividualのトラックはそのまま複製し、元のデータと参照を共有しません。Transition削除時にSlideの参照があればnullへ解除します。Slide本体の編集・表示は今回の対象外です。

## 画面値の編集と制限

位置は現在時刻の画面座標を表示・編集します。親Groupがある場合は、Animationを評価した親行列を逆変換し、子のローカル値へ戻します。片方の画面座標だけを変える操作でも、必要ならX/Y両方のローカル差分を更新し、もう片方の画面座標を保ちます。

ベース編集では、現在のAnimationがoffsetなら、その差分を加算し直さず静的ベースだけを変更します。absoluteのキーで固定されている項目はベース変更で見た目が変わらないため、更新を拒否してキーフレーム編集またはトラック削除を案内します。ベース操作だけでキーは追加しません。

Individualの位置キーを回転した親のもとで編集する場合、同時刻のX/Yキーを対で更新します。片方がない場合は拒否し、明示的な「位置キー追加 (X/Y)」で対を作るよう案内します。勝手に新しいキーを作る処理ではありません。

Child共通のキー編集は、基準をitem-000と明示しています。表示値と親変換は基準図形から求め、各子への適用時だけStaggerを使います。基準図形の同じ項目をIndividualが上書きしている場合は共通キーの編集を拒否し、個別トラックの解除を案内します。

以下の制限は該当UIにも表示しています。

- 親が正の一様scaleの場合、子の回転・倍率も画面値に換算して編集できます。
- 親が非一様・反転・0倍率の場合、子の回転・倍率の画面値編集は無効にします。未対応の値をローカル値として代わりに表示しません。
- 親が非一様scaleでも位置の逆変換は可能です。ただし行列式の絶対値が1e-12未満なら、不安定または非可逆として位置編集を拒否します。
- 幅・高さ・傾斜はローカル形状のパラメーターと明示しています。Templateも生成・Modifier・Overrides・Animationより前のローカル基本値として明示しています。
- 生成されていない子は、個数を増やして再表示するまで表示値を編集できません。保持中のOverridesは削除しません。
- キー値の表はキー時刻での表示値です。読込済みのduration外のキーは値編集を制限し、先に時刻を範囲内へ変更するよう案内します。

## 再生・cover・GPUの処理フロー

1. Editorの再生時計が実経過時間から現在時刻を求めます。フレームの回数を足して時刻を作りません。
2. `evaluateTransition` が、その時刻の位置・回転・色・形状などをCPU上で計算します。停止・シークも同じ評価器を使います。
3. 既存Rendererへ同じIDの状態を渡します。移動・回転ではMesh・Geometry・Materialを再利用し、GPUに新しい変換で三角形を描くよう指示します。
4. 選択中の図形には、同じ4頂点と行列から求めた輪郭をSVGで重ねます。ドラッグ等の直接操作はありません。
5. coverが有効でfromMs〜toMs内なら、全画面の不透明な長方形を最後に描きます。衝突を防ぐため保存Layerでは使えないスラッシュ入りの一時IDを使います。cover中は選択輪郭を隠します。
6. switchAtMsはタイムラインに目印を表示するだけで、EditorではSlideを切り替えません。
7. 一時停止は時刻を保持し、再開はその時刻から続けます。停止は0へ戻り、終端後の再生は0から始まります。非表示タブ相当の時間ジャンプでも経過時間から終端に合わせます。
8. アンマウント時はEditorのRAFを停止し、既存のRenderer / Geometry / Material / GPUDeviceを解放します。

## 保存・復元・JSONの契約

- 保存形式は `{ schemaVersion: 1, transitions: [...], slides: [...] }`。
- キーは `generative-slide-system.project.v1`。確定した編集後、約500msのデバウンスで最後のProjectを保存します。
- 初回はPhase 2のサンプルをProjectに包んで開始します。有効な保存値があれば優先します。
- 保存状態は保存中・保存済み・エラーを表示します。pagehideとEditorのアンマウントでも保留中の保存を試みます。
- 読込失敗・破損・非対応スキーマでは自動上書きを保留します。元の保存文字列は変更せず、再取得とJSON入出力の手段を残します。
- 書込失敗でも編集中のProjectは保持し、JSON出力または保存の再試行が可能です。
- JSON読込はパース・検証後に件数と置換の説明を表示し、「このJSONで置き換える」を押して初めて適用します。
- スキーマ、プレーンなJSON値、全体ID重複、SlideのTransition参照、負荷上限、cover範囲、不正・重複キー、全キー端点の結果を検証します。
- 静的ベースに対するキー端点が範囲外になる入力も拒否します。現在の数値プロパティと単調なEasingでは各項目の値域確認に使えますが、将来の複雑な制約・新Easingの全時刻の有効性を一般的に証明するものではありません。
